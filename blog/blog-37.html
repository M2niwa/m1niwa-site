一个测不出问题的指标：3D 资产验收里的五轮对抗审计

2026-10-29

有一台 18 米高的扫描机甲（原始网格 99 万面），要拆成游戏能用的零件、挂骨骼、做 LOD、接进引擎。真正难的不是这些技术活，是判断"做完了没有"。这条线上一共跑了五轮独立审计，每一轮都被要求"不得采信前面的结论，自己量"。五轮下来，最有价值的产出不是修了什么，而是发现了三种结构性失明的验收判据——它们都返回一个漂亮的数字，然后什么也没测出来。

第一种：拿源模型渲染当"真值参考"

最初的验收方法是"正/侧正交轮廓 IoU"，被用户当场否掉：只看 2D 投影，3D 可能是方块堆，游戏里照样难看。这个批评是对的。

于是方案改成：直接取原始扫描网格 → decimate 到 7 万面 → 按关节切分 → 挂关节导出。听起来是把"从零重建"换成了"改造原模型"，风险小多了。

但第二轮审计翻出了这件事：那两张被当作"真值"的 ortho_front.png / ortho_side.png，根本不是用户给的产品图。它们是用 ref_ortho_from_fbx.py 把同一个源扫描 FBX、用同一台正交相机（ortho_scale 19.6、中心 (0,0,9)、900×1400）渲出来的。而交付件就是这个网格减面加切分的结果。

所以那个 IoU 在结构上不可能失败。它只能证明"减面没把模型弄变形、切分没弄移位"，完全不能证明"像不像产品"。用户当初否定 2D IoU 是对的，而新方案只是把同一个毛病换了个包装——参考物和被测物同源，等于自己跟自己比。

这条的教训不是"别用 IoU"，而是：先问参考物是哪来的。如果参考和被测共享同一个上游，任何相似度指标都必然高分，而高分不代表任何事。

第二种：接受别人给的配准偏移

第三轮审计碰上一个更隐蔽的问题。项目脚本量出的正面 IoU 是 0.8428，脚本里先把重建图左移了 round(0.15×71.4286)=11 px——理由是"参考图体轴不在画幅中心，偏了 0.15 m"。

审计员没有直接采信这个偏移，而是对同一对图做了 ±30 px 的位移扫描：

位移IoU
−0.15 m（脚本口径）0.8428
0（同相机同画幅）0.9325
+0.15 m0.8375
±0.30 m0.777 / 0.763

峰值精确落在 dx=0, dy=0。理由不是"这样分数更高"，而是几何本身对齐：重建是用剖面提取脚本从这两张正交图逐层提的，脚本里 CX=450（画幅中心），profiles.json 里的 x 就是画幅 x——0.15 是坐标系的换算，不是两张图之间的位移。只把重建左移 0.15 m，等于把同一个偏移扣了两次。

更硬的旁证：参考正面与背视镜像在 dx=0 时 IoU = 0.9994，说明两台相机在 x=0 上互为镜像，画幅中心就是世界 x=0。

把偏移去掉之后，真实数字是正面 0.9325 / 侧面 0.9469，而不是 0.84。同时暴露出两个之前被掩盖的问题：重建高度 17.344 m 对参考 18.002 m（差 0.656 m，不过），以及左肩有一块 1.113 m² 的游离板。

这条的教训：配准偏移必须自己扫出来，不能接受别人给的数。而且"分数变高"不能作为接受某个偏移的理由——要能说出那个偏移在几何上为什么成立。

第三种：一个永远返回 0% 的穿帮指标

这是五轮里最值得写的一条。前一轮审计提出硬指标：动画时"看到内壁/背面"的像素占比必须 ≤0.1%。项目方修完之后报出的数字是——各种姿势下 0.00% 到 0.07%，全过。

终审审计员换了两种完全独立的方法复测：

  • 背面着色图：Cycles 纯自发光材质，用 Geometry→Backfacing 混合，正面灰、背面纯红，透明底。红像素 ÷ 机体像素 = 看到背面的比例。先用对照组验证判据本身：法线朝外的立方体 0% 红，翻转绕序的立方体 100% 红。
  • 几何射线：正交相机逐像素 ray_cast，记录第一击是否背面、第二击距离，按掠射修正 eff = 距离 × |n·d|。eff≈2 cm 说明是正常的 2 cm 闭合薄壳，eff>8 cm 才是真的透过开口看到内腔。

结果：

姿势背面可见 %（正/3-4）真开孔 %（正/3-4）
静止38.5 / 29.01.31 / 0.16
裙甲 35°36.4 / 28.91.28 / 0.37
屈肘 85°39.4 / 28.11.24 / 0.24
抬膝 60°38.4 / 36.31.39 / 0.21
全叠加39.0 / 35.01.19 / 1.60

静止姿势就有 38.5% 的可见面是背面，而且动画几乎不改变这个数（36–40%）——说明这是静态法线反向，不是动画撕开的口子。开孔也超标十到二十倍。

那个 0.00% 也复现出来了，而且数字是真的：Workbench 背面剔除开/关的 alpha 差确实是 0.00–0.07%。问题在于这个判据看不到问题——零件已经改成 2 cm 闭合薄壳，剔除掉近层背面之后，2 cm 后面的另一层把轮廓填满了，alpha 永远不空，差值必然为 0。它测的是"有没有空像素"，不是"看到的是不是内壁"。

根因后来也查清了：网格里有 1,129 条非流形边，normals_make_consistent(inside=False) 在这种网格上判不出"外面"，于是逐岛方向随机。这个毛病不是最后一步引入的——三个版本的背面率分别是 39.0% / 31.5% / 37.3%，四轮里一直存在，只是之前没人量过背面。GLB 里也能独立看到：21 件里有 8 件签名体积为负。

顺带被推翻的两件事

一，"21 件全部闭合"不成立。逐件查边界边，总共 514 条，而且每一条长度都恰好 0.02（总周长 10.28）——这是 Solidify 的 rim 没焊上的 2 cm 缝，不是大洞。真正的闭合件只有 2 个。

二，游戏截图不能当穿帮判据。四视图里机体只有约 150 px 高、头部不到 30 px，还叠着准星、MISSION START 横幅和挂载武器。这个分辨率下"看不出双影"没有任何信息量。另外侧视图背包后方有一簇疑似脱开的深色碎块，但按配置查，位置和形状都对得上挂载的弹舱/砍刀，当前证据无法确证——审计员把这条写成了"大概率是挂载件，但证据不足"，没有硬判。

结果与代价

终审结论是"还需 2 轮"，不是通过。但同时确认了三项真实进步：开孔从 2.04–2.82% 降到 0.16–1.60%；面数预算从"大腿 311 面 vs 躯干 11,656 面"（37 倍失衡）修到 0.29 的合理比；以及"截图早于最终 GLB"的时序缺口补上了——GLB 12:27:36 写入 → 12:27:47 重导入 → 12:27:57 出图 → 12:28:12 提交，链条闭合。

形态那条也没过：头部缺面罩和 V 鳍，而那是整台机最认人的特征，只能算"同一族、不是同一台"。

这套流程真正的成本不在算力，在每一轮都要重新建立"我怎么知道"。审计员要自己写 GLB 解析器、自己定掩膜口径、自己设计对照组验证判据本身。但换来的东西也很明确：三个"返回漂亮数字但什么也没测"的判据被逐个揪出来，其中一个（0.00% 穿帮率）如果没人复测，会一直躺在交付报告里当证据。

能带走的三条

一，一个不可能失败的判据不是判据。参考物和被测物同源、或者判据的物理前提被改动消掉了（薄壳填满轮廓），指标就必然恒为最优值。设计判据时先问：什么情况下它会失败？答不出来就是没在设计判据。

二，自己扫参数，别接受别人给的偏移。0.15 m 的位移让分数从 0.93 掉到 0.84，而它被当成"正确的口径"写进了脚本。这种错误不会报错，只会让一个正常的资产看起来不合格——或者反过来。

三，自证不等于他证。"我量了 0.00%"和"别人独立量了 0.00%"是两件完全不同的事。前者只证明判据能跑，后者才证明结论成立。这条线上的五轮审计，每一轮的价值都来自"我不看你给的数"。
